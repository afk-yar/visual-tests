# Свод времени и стоимости решений

Конвейер собирает из логов Claude Code и Codex, сколько времени, токенов и денег
ушло у каждой модели на решения витрины. Результат — `assets/compare-data.js`,
его показывает страница `compare.html` (пункт «Сравнение моделей» в сайдбаре).

Считаются только исполнители: субагенты и сессии Codex, которые писали решение.
Оркестратор идёт отдельной справочной цифрой.

## Как обновить

```
python tools/compare/run.py            # пересканировать логи и собрать
python tools/compare/run.py --build    # только собрать из data/*.json
```

После сборки открыть `http://localhost:8473/compare.html`, проверить страницу,
закоммитить `assets/compare-data.js` вместе с `tools/compare/data/`.

## Добавить новую модель или сессию

1. **Модель** — строка в `MODELS` в `config.py`: `label`, `slug` как в `manifest.js`,
   `tool`, `model_ids` (id модели в логах), `why`. Цена — строка в `PRICING`.
2. **Решения в Claude Code** (субагенты) — строка в `CLAUDE_SESSIONS`:
   `label` и `session` — id главной сессии, это имя файла `<id>.jsonl` в
   `~/.claude/projects/E-----------pet-visual-tests/`. Последняя сессия там —
   самый свежий по времени файл. Если после решений сессия ушла в другую работу,
   поставить `orchestrator_cutoff` — время (UTC) первой реплики той работы.
3. **Решения в Codex** настраивать не нужно. Скан сам находит все сессии с рабочей
   папкой `visual-tests*` и узнаёт задачу по началу её промпта. Исключение — одна
   сессия на несколько задач, она задаётся в `CODEX_SHARED`.
4. `python tools/compare/run.py` и сверить итоги в выводе: задач с данными
   у модели столько, сколько её решений в манифесте.

## Как устроено

| Шаг | Что делает | Результат |
|---|---|---|
| `scan_claude.py` | разбирает транскрипты субагентов `<сессия>/subagents/agent-*.jsonl` | `data/claude_runs.json` |
| `scan_codex.py` | разбирает `~/.codex/sessions/**/rollout-*.jsonl` | `data/codex_runs.json` |
| `scan_orchestrators.py` | считает реплики главных сессий | `data/orchestrators.json` |
| `build.py` | выбирает прогоны, считает стоимость | `assets/compare-data.js` |

`config.py` — пути, цены, модели, сессии и ручные поправки. `common.py` — общие функции.

**Данные `data/*.json` хранятся в git, потому что логи не вечные.** Claude Code
удаляет транскрипты старше `cleanupPeriodDays` (с 2026-09-26 — 365 дней, до этого 30).
Если каталога сессии больше нет, скан берёт её строки из сохранённых данных, а не
теряет их. Поэтому после скана коммитить надо и `data/`. Логи Opus 5 уже были
восстановлены из restic-снимка `1726c119`, их данные живут только в `data/`.

## Правила подсчёта

- **Токены Claude Code.** Одна API-реплика пишется несколькими строками с одним
  `message.id`, и `usage.output_tokens` растёт от строки к строке. Берётся последняя
  строка на `message.id`, строки `model: "<synthetic>"` отбрасываются.
- **Токены Codex.** Событие `token_count` несёт накопительный `total_token_usage`,
  берётся последнее значение. `input_tokens` включает `cached_input_tokens`,
  `output_tokens` включает reasoning. Модель берётся из `turn_context`.
- **Первая версия** — от первой записи исполнителя до его последнего ответа перед
  первым сообщением критики. Служебное «Output token limit hit» — продолжение
  первой версии. Доработка, починка и перезапуски считаются отдельно. Сообщения
  критики надо помечать `[ДОРАБОТКА]` или `[ПОЧИНКА]`, по меткам определяется вид правки.
- **Какой прогон — решение.** В Claude Code доработка обычно идёт в том же субагенте
  через SendMessage, и скан делит его сам. Если по задаче несколько субагентов,
  субагент с описанием «Доработка …» считается доработкой, из остальных решение —
  самый поздний, более ранние — перезапуски. В Codex решение — самый поздний прогон
  по задаче.
- **Паузы ожидания в часы** из времени вычитаются вручную через `IDLE_FIX`.
  Длинный разрыв внутри прогона сначала проверить: 20 минут перед ответом
  в 128 тыс. токенов — это генерация, а не простой.
- **Стоимость** — оценка по прейскуранту API, а не списания по подписке.
